# Подключение облака и личного кабинета

Приложение остаётся статическим сайтом GitHub Pages. Supabase отвечает за аккаунты и личные библиотеки. Пока параметры не заданы, локальный режим работает, а личный кабинет сообщает, что облако не подключено. Существующий ключ хранения и данные не меняются.

## 1. Создать хранилище в существующем проекте

Откройте свой проект в https://supabase.com/dashboard → **SQL Editor → New query**. Скопируйте весь файл [supabase/migrations/202611040001_library_sync.sql](supabase/migrations/202611040001_library_sync.sql), вставьте и нажмите **Run**.

Скрипт создаёт таблицу `public.moya_libraries`, политику чтения только собственных данных и функцию `public.save_moya_library`. Эти имена предназначены для этого приложения; перед выполнением проверьте, что они не используются другим приложением. Пароль базы не нужен. Скрипт можно повторить для этой же схемы.

## 2. Настроить вход и письма

В **Authentication → Sign In / Providers** включите провайдер **Email** и регистрацию пользователей. Подтверждение email рекомендуется оставить включённым. У новых проектов встроенная отправка писем Supabase имеет ограничения: для обычных пользователей настройте собственный SMTP в настройках Auth Email. Проверьте доставку письма подтверждения и восстановления пароля с реальным адресом; тестовый API этого не проверяет.

В **Authentication → URL Configuration** укажите:

- **Site URL:** `https://avtaiaai-spec.github.io/library/`
- **Redirect URLs:** `https://avtaiaai-spec.github.io/library/`

Точные названия разделов могут отличаться в текущем интерфейсе Supabase. Для локальной разработки отдельно разрешите нужный localhost URL; адрес production менять не нужно.

## 3. Найти публичные параметры

В **Project Settings → API / Data API** скопируйте **Project URL** вида `https://PROJECT.supabase.co`.

В **Project Settings → API Keys** скопируйте **Publishable key** (`sb_publishable_…`). Для старых проектов допускается публичный `anon` key. Эти параметры предназначены для браузера и видны в собранном приложении. **Secret / service_role key и пароль базы запрещено добавлять в VITE-переменные.** Доступ к данным ограничивает серверная RLS-политика, а не скрытность публичного ключа.

## 4. Подключить опубликованный сайт

Откройте GitHub → репозиторий **avtaiaai-spec/library → Settings → Secrets and variables → Actions → Variables → New repository variable**.

Создайте две переменные:

| Имя | Значение |
| --- | --- |
| `VITE_SUPABASE_URL` | Project URL из Supabase |
| `VITE_SUPABASE_PUBLISHABLE_KEY` | Публичный Publishable key |

Затем откройте **Actions → Publish library to GitHub Pages → Run workflow → main → Run workflow**. Переменные попадают в приложение во время сборки; изменение переменных без новой сборки не активирует облако.

Для облачной среды Codex задайте эти же две переменные в настройках среды и разрешите HTTPS-доступ к точному домену своего проекта Supabase. Для локального запуска можно скопировать `.env.example` в `.env.local` и заполнить значения. Не коммитьте `.env.local`; после изменения перезапустите Vite.

## 5. Первый перенос и проверка

Перед переносом скачайте JSON-копию текущей библиотеки в настройках приложения.

1. После успешной публикации откройте сайт и обновите приложение через настройки.
2. Нажмите значок пользователя **«Личный кабинет»**, зарегистрируйтесь и подтвердите email, затем войдите.
3. На устройстве с вашей библиотекой выберите **«Перенести эту библиотеку в облако»** и подтвердите выбор.
4. На втором устройстве войдите в тот же аккаунт, выберите **«Открыть облачную библиотеку»** и подтвердите. Локальная библиотека второго устройства будет заменена; при необходимости сначала скачайте её копию.
5. Добавьте книгу на первом устройстве, дождитесь синхронизации. На втором нажмите **«Синхронизировать»** или вернитесь в приложение. Убедитесь, что книга появилась. Повторите с цитатой и прогрессом чтения.
6. Отключите сеть, измените книгу, включите сеть и убедитесь, что изменения отправились.
7. Одновременно измените данные на двух устройствах: приложение должно предложить выбрать версию. Можно скачать обе копии. Автоматического объединения нет.
8. Проверьте выход, повторный вход, подтверждение email и восстановление пароля. После выхода книги остаются в браузере; учитывайте это на общем устройстве.

Синхронизируются книги, цитаты, полки, теги и годовые цели. Настройки открытого экрана и фильтров не синхронизируются. Открытые редакторы и экран настроек приостанавливают обмен, чтобы не терять несохранённый ввод; после завершения перейдите в личный кабинет. Синхронизация проверяется раз в 15 секунд, после сохранения, при возвращении в приложение и восстановлении сети. Закрытая вкладка не отправляет изменения в фоне.

## Проверки для разработки

- `npm test` — модель библиотеки и сценарии синхронизации, включая конфликты, сбой сети, изменения во время запроса и выход из аккаунта.
- `npm run test:cloud-db` — настоящая SQL-миграция в локальном PostgreSQL PGlite с тестовыми Auth-ролями: изоляция пользователей, запрет прямой записи, атомарная проверка ревизий. Это не проверка удалённого проекта Supabase.
- `npm run build -- --base /library/` — сборка GitHub Pages.
- Браузерный тест подключённого кабинета работает с контролируемым API: запустите Vite с `VITE_SUPABASE_URL=https://library-test.supabase.co` и `VITE_SUPABASE_PUBLISHABLE_KEY=sb_publishable_test_only` на порту 5175; выполните `PLAYWRIGHT_CLOUD_TEST=1 PLAYWRIGHT_BASE_URL=http://127.0.0.1:5175 npx playwright test tests/account.spec.ts --workers=1`.

Для полноценной готовности необходимо выполнить шаг 5 на настоящем проекте и двух устройствах. Успешные локальные тесты не подтверждают отправку писем, доступ к проекту или публикацию сайта.
